# 訓練計劃行事曆 App — 設計文件

日期：2026-09-03
使用者：54 歲，173 cm，68 kg → 目標 75 kg、體脂 15–18%（增肌減脂／體態重組，12–24 個月）
器材：8 kg 啞鈴 × 2、滾輪、單槓、健身椅

## 1. 目標與範圍

把既有的一份訓練＋飲食計劃做成一個「可視、可打卡」的行事曆應用程式。使用者不懂健身專有名詞，因此每個動作**一定要看得到怎麼做**（動畫示範 + 白話步驟）。

三大功能：
1. **行事曆**：把每週固定循環的課表自動鋪到每一天。
2. **當日打卡**：看動作示範、記錄每組重量/次數、勾選飲食。
3. **進度追蹤**：體重週均、圍度、力量指標、階段目標、熱量微調提醒。

**非目標（YAGNI）**：多使用者、雲端同步、帳號登入、社群、營養資料庫自動計算、真人影片（日後可加）。

## 2. 技術形式

- **資料夾版**單機應用，無框架、無 build、無需伺服器、離線可用。
- 結構：
  ```
  workout-planner/
  ├─ index.html        主程式，HTML/CSS/JS 全內嵌（vanilla JS）
  ├─ plan.js           課表與飲食範本的靜態資料（動作清單、組數、範圍、升級階梯、飲食）
  ├─ exercises.json    本 App 用到的動作之中文步驟、肌群、GIF 檔名（從 dataset 萃取）
  └─ gifs/             從 dataset 挑出的 ~25 個動作動畫 GIF
  ```
- 使用方式：**雙擊 `index.html`** 於瀏覽器開啟（`file://`）。
- 資料儲存：瀏覽器 **localStorage**；提供「匯出 JSON / 匯入 JSON」按鈕做備份與跨機搬移。
- 版面：桌面優先；彈性排版讓手機也可用。

## 3. 訓練排程（每週固定循環）

| 週一 | 週二 | 週三 | 週四 | 週五 | 週六 | 週日 |
|--|--|--|--|--|--|--|
| 上半身 A | 下半身 A + 核心 | 有氧/休息 | 上半身 B | 下半身 B + 核心 | 輕鬆跑/快走 | 完全休息 |

自動依星期幾把對應課表鋪到月曆每一天（不需使用者逐日排課）。

6. 二頭彎舉 — 3 × 10–15

**下半身 A + 核心**

2. 保加利亞分腿蹲 — 4 × 8–15 /腿
3. 啞鈴羅馬尼亞硬舉 — 4 × 10–15
4. 單腿臀推 — 3 × 12–20 /腿
5. 滾輪 — 3 × 6–15
6. 側棒式 — 3 × 30–60 秒 /側

**上半身 B**
1. 引體向上 — 5 組（不必每組力竭，例 8/7/6/5/5）
2. 啞鈴上斜臥推 — 4 × 8–15

## 4. 畫面設計

三個分頁：**行事曆 / 當日詳情 / 進度**。

### 4.1 行事曆
- 月曆檢視，可切換上一月／下一月。
- 每格顯示：日期 + 當天課表類型標籤（上半身 A、下半身 A、有氧、休息…）+ 完成狀態小圓點：
  - 灰＝未開始、半＝部分完成、實心＝全部完成。
- 點某天 → 進入「當日詳情」。今天有明顯標示。

### 4.2 當日詳情
上半部＝訓練；下半部＝飲食。

**動作卡片**（每個動作一張）：
- 動作名稱（白話）＋一句「這在練哪裡」。
- **動畫 GIF**（循環播放整個動作）。
- 3–4 步**白話文字步驟**（無專業術語，例：①躺在椅子上 ②啞鈴推到胸口上方 ③慢慢放下約 3 秒）。
- 目標：`4 組 × 8–15 下`，並標「做完還能再做 1–3 下就停，不用做到力竭（RIR 1–3）」。
- 每組一列輸入：**重量 (kg) / 次數**，可勾選該組完成。
- 若觸發升級條件，卡片頂端顯示**升級提示**（見 §5）。

**飲食卡片**：見 §6。

### 4.3 進度
- **體重**：輸入每次晨起空腹體重（建議每週 3–4 次）；自動算**週平均**並畫趨勢線。
- **階段目標進度條**：68→70→72→74→75 kg，標出目前週均落點。
- **圍度（每月）**：體重／腰圍／胸圍／手臂／大腿，輸入與歷史列表。
- **力量指標**：引體向上次數、主要啞鈴動作次數趨勢（取自打卡紀錄）。
- **熱量微調提醒**：見 §7。

## 5. 漸進超負荷（自動升級提示）

每個動作有目標次數範圍（如 8–15）。**升級判定**：使用者某動作**最近一次**打卡中，**所有目標組都達到範圍上限**（例：四組都 ≥15 下），則下次打開該動作時於卡片頂端顯示升級提示，並依**升級階梯**建議下一項（一次只加一項）：

> 增加次數 → 增加組數 → 放慢離心 → 增加動作幅度 → 單側訓練 → 減少休息

- App 記錄每個動作目前的「升級階段」索引；升級提示被使用者接受後階段 +1，並在動作目標旁顯示目前套用的方法（如「下放放慢 4 秒」）。
- 對「盡可能多次」型動作（引體向上、窄握伏地挺身）：不套用範圍上限判定，改以「次數持續成長」呈現於進度指標，不跳升級提示。

## 6. 飲食模組（固定範本 + 蛋白質勾選）

每天顯示固定四餐範本 + 睡前補充，每餐一個勾選框：

- **早餐**：雞蛋、無糖豆漿、燕麥、香蕉
- **午餐**：飯、雞肉／魚／牛肉、蔬菜
- **下午**：豆漿、香蕉、堅果
- **晚餐**：飯、魚／雞肉／瘦牛肉、豆腐、蔬菜
- **睡前（當日蛋白質不足時）**：豆漿、無糖優格

卡片上方顯示每日目標：**2,400–2,600 kcal、蛋白質 ~130 g**，以及「今日已勾選 X / 5 餐」。（本階段不做熱量自動加總；範本即目標。）

## 7. 熱量微調提醒（進度分頁）

依週平均體重變化自動提示（僅提示，不自動改任何數字）：
- 連續 **2–3 週**週均沒有增加 → 提示「每天增加約 150–200 kcal」。
- 每週增加 **> 0.4 kg** 且腰圍同步變粗 → 提示「每天減少約 150–200 kcal」。
- 理想速度：每月約 +0.5 kg。

## 8. 資料模型（localStorage，單一 JSON）

```
{
  "version": 1,
  "logs": {
    "2026-09-03": {
      "exercises": {
        "<exerciseId>": { "sets": [ {"weight": 8, "reps": 12, "done": true}, ... ] }
      },
      "cardioDone": false,
      "meals": { "breakfast": true, "lunch": false, ... }
    }
  },
  "progression": { "<exerciseId>": { "stageIndex": 0 } },
  "bodyweight": [ { "date": "2026-09-01", "kg": 68.0 }, ... ],
  "measurements": [ { "date": "2026-09-01", "waist": 82, "chest": 98, "arm": 33, "thigh": 54, "kg": 68.0 }, ... ]
}
```

- `plan.js`（靜態）定義每日課表、動作、目標範圍、升級階梯、飲食範本。
- `exercises.json`（靜態）定義每個動作的中文步驟、肌群、GIF 檔名。
- 使用者資料只存在 `logs / progression / bodyweight / measurements`。
- **匯出／匯入**整包 JSON 做備份。

## 9. 錯誤處理與邊界

- localStorage 讀不到或損毀 → 以空白初始狀態啟動，不中斷。
- GIF 檔缺失 → 顯示占位圖與動作名稱，不讓卡片崩壞。
- `file://` 下 localStorage 可用（單機單人足夠）；匯出 JSON 作為額外保險。
- 未來日期／過去日期皆可檢視與補登。

## 10. 測試策略

- 純函式（升級判定、週均計算、熱量提醒判定）以可在瀏覽器 console 或簡單測試檔驗證的方式撰寫（輸入 → 預期輸出）。
- 手動驗收清單：鋪課表正確對應星期、打卡後圓點狀態變化、達上限後跳升級提示、體重輸入後週均與進度條更新、匯出後匯入資料一致。
